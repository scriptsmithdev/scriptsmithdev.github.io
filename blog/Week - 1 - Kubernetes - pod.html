Understanding Kubernetes Pods

By Felix Amoah | DevSecOps Bootcamp

Week 1 — Kubernetes

What Is a Pod?

One of the first Kubernetes concepts I had to understand was the Pod. Coming from a Docker background, I initially thought a Pod was simply another name for a container. It is not.

A Pod is the smallest deployable unit in Kubernetes. A Pod can contain one or more containers that share the same network namespace and can communicate with each other using localhost.

In most basic applications, a Pod contains a single container. However, Kubernetes also supports multi-container Pods when containers need to work closely together.

Creating My First Pod

I experimented with creating a simple Pod using a Kubernetes YAML manifest. The manifest describes what I want Kubernetes to run. 


```

apiVersion: v1
kind: Pod
metadata:
name: nginx-pod
spec:
containers:
- name: nginx
image: nginx:latest
```

After creating the configuration file, I can deploy it using: 

kubectl apply -f pod.yaml

I can then check whether the Pod is running with: 

kubectl get pods

Troubleshooting a Pod

One of the useful things I discovered is that Kubernetes provides several commands for troubleshooting workloads. For example, kubectl describe pod nginx-pod provides detailed information about the Pod, including events and container status.

I can also use kubectl logs nginx-pod to inspect the application's logs. These commands are important because a Pod may exist in the cluster without the application inside it actually working correctly.

What I Learned

The biggest lesson for me was understanding that Kubernetes manages Pods rather than treating individual containers as the primary deployment object.

I also learned that Kubernetes is declarative. Instead of manually telling Kubernetes every step it needs to perform, I describe the desired state in a YAML file and Kubernetes works toward maintaining that state.

DevSecOps Connection

From a DevSecOps perspective, this becomes particularly interesting when security is introduced into the deployment process. Kubernetes manifests, container images, secrets, network policies, and access permissions all need to be considered before an application reaches production.

My next goal is to move from manually creating Pods to using Deployments and Services, and eventually connect these concepts to CI/CD automation.
